# Tests and fixtures

## Run the checks

| Command | Role |
|---------|------|
| `bun run test` | Unit and contract tests (Vitest, happy-dom environment). **Not** `bun test`. |
| `bun run test:watch` | Watch mode. |
| `bun run test:coverage` | Tests with V8 coverage: summary in the terminal, `coverage/lcov.info` for SonarQube Cloud. Not part of `bun run ci`; the percentage is informational, no threshold is enforced. |
| `bun run test:build` | Checks the production manifest (permissions, CSP); run **after** `bun run build`. |
| `bun run typecheck` | Types (`vue-tsc --noEmit`). |
| `bun run lint` | ESLint. |
| `bun run check:config` | Repository settings: JSON(C), YAML, Bun version, issue templates and labels, `en`/`fr` catalog parity. |
| `bun run ci` | Everything, in order: check:config, typecheck, lint, test, build, test:build. |

GitHub CI runs the same checks on pull requests and on `main`; run **`bun run ci` locally before every push** to catch errors early. An
optional `pre-push` hook can run it automatically (`bun run setup` offers it).

## Layout of `tests/`

| Folder | Content |
|--------|---------|
| `tests/unit/` | Parsers per page language, Amazon extractor per store, download, PDF, URL rule, key encryption, settings storage, router, duplicates, theme, translation catalogs (including `en`/`fr` parity), privacy, text rendering. |
| `tests/contract/` | HomeBox client and import orchestrator against a **simulated** API (success, 401, network error, non-JSON response, attachment failure after creation, recovery). |
| `tests/build/` | Check of the produced manifest (exact permissions, no static `host_permissions`, optional host permissions, CSP). |
| `tests/fixtures/` | Anonymized order pages (see below). |

## Anonymized fixtures

Each extractor is tested on recorded HTML pages, one folder per Amazon store:
`tests/fixtures/amazon-<store>/` (`amazon-fr`, `amazon-de`, `amazon-es`, `amazon-it`, `amazon-com-be`,
`amazon-nl`, `amazon-co-uk`, `amazon-com`), each with a README (date, method, table of the fixtures).

- **`real-*.html`**: structure of a real order page, content 100 % fictional, produced by
  `scripts/fixtures/anonymize-amazon.ts` (allow list, leak check). Amazon.fr has them.
- **`reconstructed-*.html`**: pages generated by `scripts/fixtures/reconstruct-amazon.ts` from the
  anonymized Amazon.fr pages only (language, labels, dates and prices of the store); the script never
  reads a `raw/` folder. They cover the stores still "testing": a simple order, a multi-product order and an
  order with invoice, plus language variants (Amazon.de in English and Turkish, Amazon.com.be in French
  and Dutch).
- Hand-written synthetic pages cover the remaining Amazon.fr cases (old layout, page that is not an
  order...).

A store moves from `testing` to `supported` only once a `real-*.html` fixture exists in its folder: the
status changes in `src/content/merchants/amazon/stores.ts`, `MERCHANTS.md` and `MERCHANTS.fr.md` in the
same pull request (tests check the three).

### Add or replace a fixture

1. On an order details page: right-click, "Save as", *Webpage, HTML only*, into
   `tests/fixtures/amazon-<store>/raw/` (folder **ignored by git**, never commit it, never attach it to an
   issue).
2. Run the local tool: `bun scripts/fixtures/anonymize-amazon.ts amazon-<store> <raw file> real-order-single.html <language>`.
   It keeps only the `#orderDetails` subtree with an allow list, replaces every text with a generated
   value, then runs the **leak check** (every value of the raw page searched in the fixture): the fixture
   is written only if it finds 0 leak. The tool prints counts only, never a value of the page.

For a hand-written synthetic fixture instead:

1. Save the page into `raw/` as above.
2. Copy the file out of `raw/`, then:
   - remove the `<script>`, `<style>`, `<link>`, `<iframe>` tags and the comments;
   - replace the name, the delivery address and the payment method with fictitious values
     (`Jean Exemple`, `1 rue Fictive`, `Carte se terminant par 0000`, the placeholders already used by the
     existing fixtures, since the Amazon.fr pages are in French);
   - replace the order number with `999-0000000-00000NN` and the document identifiers
     (`/documents/download/<uuid>/`) with fictitious UUIDs;
   - keep the DOM structure (tags, classes, `data-*` attributes).
3. Check that nothing personal remains:
   `grep -iE "@|\+[0-9]{2}|\+1[ (]|\b0[67][0-9 ]{8}\b|<script" file.html` must return nothing (phone
   formats `+49`, `+44`, `+1`... included).
4. Note the capture date and the page type in the folder's README (never the real address).

### When Amazon changes its layout

1. Capture and anonymize the new page as above.
2. Add a test that **fails** on this fixture (`tests/unit/amazon-stores-extractor.test.ts`, or
   `tests/unit/amazon-fr-extractor.test.ts` for Amazon.fr).
3. Fix **only** `src/content/merchants/amazon/selectors.ts` (selectors) or
   `src/content/merchants/amazon/page-locales.ts` (labels and month names of a page language), adding
   fallbacks rather than replacing the old ones when possible.

A selector fix without a fixture reproducing the new structure is not accepted.

## Notable automatic checks

- The `en` and `fr` catalogs have the same keys and the same substitutions; the literal translation keys
  used in `src/` exist in the catalog, each error code has its message, no catalog value is empty.
- The rendering of the "Unencrypted HTTP" warning matches the catalog exactly.
- The duplicate search looks for the order number in quotes and compares normalized names.
- The URL rule is tested, including against public names that imitate a private IP.
- The production manifest is compared with the exact list of allowed permissions.
